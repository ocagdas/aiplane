## Current implementation: portable agent guardrails

`agents guardrails render|validate` now produces and verifies a packaged `aiplane-agent-guardrails-v1` JSON contract. Agent manifests include the same deterministic contract; `render` also accepts repeatable numeric `--limit key=value` overrides, while `agents export --file guardrails.py` emits a small Python callback adapter for framework-owned loops. The adapter enforces configured wall-time, model/tool/retry counts, input/output/total tokens, and immediate USD cost observations through in-process callbacks; it does not launch, proxy, supervise, or terminate agents. The default scope is one non-durable local run. Delayed provider billing reconciliation and shared/distributed ledgers remain deliberately deferred because they cannot provide an immediate hard stop. Focused contract, CLI, schema-packaging, and existing agent-framework tests cover this slice.


## Current implementation: evidence-to-handoff

`models handoff-plan` composes existing role routing, controlled local/imported calibration status, runtime capacity guidance, optional client integration plans, and optional agent/guardrail metadata into a secret-free, checksummed, render-only artifact. It never applies configuration, starts a runtime, or starts an agent. Guardrail adapters can now write an atomic, opt-in local receipt only when `AIPLANE_GUARDRAILS_RECEIPT_PATH` is supplied; `agents guardrails receipt` validates it within the profile workspace. Read-only MCP tools mirror handoff planning and receipt inspection. `models handoff-validate` verifies a saved handoff's schema identity, profile scope, checksum, workspace boundary, and secret safety; every framework starter now names the callback boundary where its project should use the exported adapter. Calibration remains local/imported and no provider billing API, hosted exchange, distributed ledger, model proxy, or process supervision is added.
